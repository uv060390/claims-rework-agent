# Data dictionary — synthetic claims rework dataset

Generated by `data/generate_rework.py` (deterministic per seed). The frozen demo set in
`data/demo/` uses `--n-requests 5000 --seed 42`. **All data is synthetic**: NPIs are
random but Luhn-valid, members and providers are invented, and fee-schedule amounts are
illustrative values loosely based on public CMS Physician Fee Schedule national amounts.
Code sets (CPT/HCPCS, ICD-10-CM, POS, CARC) come from public CMS/X12 documentation —
see `pipeline/datagen/codes.py`.

Ground truth ships in a **separate file** from the requests: pipeline code reads
`claims.csv` + `rework_requests.csv` only; `ground_truth.csv` exists for training the
classifier and scoring evals. Nothing in the request rows leaks the label.

## claims.csv (one row per claim line)

| Column | Type | Notes |
|---|---|---|
| `claim_id` | str | `CLM-XXXXXXXX`; unique |
| `member_id` | str | `MBR-XXXXXXX`; synthetic member |
| `provider_npi` | str | 10 digits, valid Luhn check digit, not a real provider |
| `provider_name` | str | synthetic practice name |
| `service_date` | date | date of service (2025) |
| `submitted_date` | date | claim submission date; drives timely-filing math |
| `cpt_code` | str | behavioral-health CPT/HCPCS (90791–96130, H-codes) |
| `modifiers` | str | space-separated (95, GT, HO, HN, 25); may be empty |
| `icd10_code` | str | ICD-10-CM F-code diagnosis |
| `pos_code` | str | place of service (02/10 telehealth, 11 office, 53 CMHC, …) |
| `units` | int | service units billed |
| `billed_amount` | decimal | provider billed charges |
| `allowed_amount` | decimal | fee-schedule allowed amount |
| `paid_amount` | decimal | amount actually paid (0.00 when denied) |
| `status` | str | `paid` \| `partial` \| `denied` |
| `denial_carc` | str | CARC code when denied (18, 29, 45, 97, 197, …); else empty |
| `original_claim_id` | str | set on duplicates/resubmissions; else empty |

`claims.csv` contains more rows than there are requests: duplicate/resubmission
scenarios also emit the *original* claim so the pipeline can look it up.

## rework_requests.csv (one row per rework request — pipeline input)

| Column | Type | Notes |
|---|---|---|
| `request_id` | str | `RWK-XXXXXX`; unique |
| `claim_id` | str | the claim being disputed |
| `received_date` | date | when the rework request arrived |
| `requester_type` | str | `provider` \| `internal_audit` \| `member_advocate` |
| `resubmission_count` | int | prior requests on this claim |
| `has_attachment` | bool | supporting documentation supplied |
| `note` | str | free-text request note; honest or misleading, like real queues |

## ground_truth.csv (one row per request — labels; never read by the pipeline)

| Column | Type | Notes |
|---|---|---|
| `request_id` | str | joins to `rework_requests.csv` |
| `scenario_id` | str | one of 13 generating scenarios (below) |
| `correct_action` | enum | `no_change` \| `adjust_up` \| `adjust_down` \| `uphold_denial` \| `reprocess` \| `route_specialist` |
| `correct_adjustment_amount` | decimal? | set iff action is `adjust_up`/`adjust_down` |
| `no_adjustment_needed` | bool | derived: action ∈ {`no_change`, `uphold_denial`} — the classifier's target |
| `favorable_to_provider` | bool | derived: action ∈ {`adjust_up`, `reprocess`} — drives the STP gate |
| `clear_cut` | bool | resolvable by the deterministic rules layer |

## Scenario catalog (13)

| scenario_id | correct action | favorable | clear-cut | The situation |
|---|---|---|---|---|
| `underpaid_fee_schedule` | adjust_up | ✓ | ✓ | paid below fee-schedule allowed; delta owed |
| `overpaid_recoupment` | adjust_down | — | ✓ | audit found overpayment; recoup |
| `correct_payment_dispute` | no_change | — | — | payment was correct; provider disputes anyway |
| `true_duplicate` | uphold_denial | — | ✓ | CARC 18 denial is right; original was paid |
| `corrected_resubmission_denied_as_dup` | reprocess | ✓ | — | denied as dup, but "original" was itself denied |
| `timely_filing_expired` | uphold_denial | — | ✓ | filed past the 90-day limit, no exception |
| `timely_filing_exception` | reprocess | ✓ | — | late claim with proof of timely original submission |
| `auth_denied_in_error` | reprocess | ✓ | — | CARC 197 but a valid auth is on file |
| `missing_auth_valid_denial` | uphold_denial | — | — | no auth exists; denial stands |
| `cob_conflict` | route_specialist | — | — | coordination-of-benefits dispute; needs COB desk |
| `wrong_units_underpaid` | adjust_up | ✓ | — | 2 units rendered, 1 paid |
| `bundled_service_denial` | uphold_denial | — | ✓ | CARC 97 bundling denial is correct |
| `telehealth_modifier_denial` | reprocess | ✓ | — | telehealth claim missing modifier 95, corrected |

Demo-set shares (seed 42, n=5000): `no_adjustment_needed` 44.0%, `clear_cut` 42.4%,
`favorable_to_provider` 44.5%.
